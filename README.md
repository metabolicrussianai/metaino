# inoagent_check

Оффлайн-утилита вычитки документов на упоминания лиц и организаций из реестра иностранных агентов Минюста России.

**Назначение:** помощь редакциям, издательствам и авторам в соблюдении требований к маркировке.
**Не предназначена** для составления списков лиц, массового сканирования чужих корпусов и автоматического удаления контента. Утилита выдаёт отчёт человеку; решение принимает человек.

**Не является юридической консультацией.**

---

## Зачем это нужно

С 2025 года суды начали применять часть 42 статьи 19.5 КоАП РФ — невыполнение в установленный срок предписания или предупреждения органа, контролирующего законодательство об иноагентах. Санкции: граждане 30–50 тыс. руб., должностные лица 70–100 тыс. руб. или дисквалификация до двух лет, юридические лица 200–300 тыс. руб.

Механика определяет, что именно проверяет утилита:

1. Обязанность маркировать материалы иноагента возложена законом на **СМИ**. Граждане и организации без статуса такой прямой обязанности не имеют.
2. Риск возникает иначе: если иноагент сам не поставил маркировку, распространение его материала трактуется как содействие ему в нарушении. Минюст выносит предупреждение, даёт срок на устранение, и только неисполнение предписания образует состав по части 42.
3. Отсюда практический вывод: **репост материала, в котором авторская плашка уже стоит, риска по этой норме не создаёт.**

Поэтому утилита проверяет не только наличие имени, но и наличие маркировки рядом с упоминанием.

Для продукции СМИ требования жёстче: маркировать нужно любое упоминание, на всех площадках присутствия редакции.

## Что считается надлежащей маркировкой

### Действующая форма (для самих иноагентов)

Утверждена постановлением Правительства РФ от 22.11.2022, в силе с 1 декабря 2022 года. Начинается словами «Настоящий материал (информация)…», далее указывается наименование или Ф. И. О. **в точности как в реестре**.

Требования к оформлению текстовой плашки:

- размещение под заголовком материала, а при отсутствии заголовка — в начале материала;
- размер шрифта **вдвое больше** размера шрифта основного текста;
- цвет, контрастный к фону; наложение на текст или изображение недопустимо;
- в аудио- и видеоматериалах — демонстрация не менее 15 секунд.

Маркировка требуется, если материал касается иноагентской деятельности. Личные материалы, не относящиеся к такой деятельности, маркировать не требуется.

### Форма для лиц без статуса — НЕ ДЕЙСТВУЕТ

Проект приказа Минцифры о единой маркировке сообщений, содержащих материалы иноагентов и распространяемых лицами без такого статуса, был опубликован 31 января 2025 года; предполагалось вступление в силу 1 сентября на шесть лет.

**На дату 23.08.2026 проект в силу не вступил.**

Файл `forms/mincifry_draft.txt` включён как справочный, помечен `status: not_in_force` и текста плашки не содержит сознательно. Не подставляйте его клиентам как обязательный.

### Свободное упоминание

Обязательной формы для не-СМИ при простом упоминании имени нет. Практика юристов — указывать статус всегда, любым однозначным способом. Утилита не навязывает формулировку: она показывает упоминание и отсутствие рядом какого-либо указания на статус.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install requests            # только для update --url
pip install python-docx         # чтение docx
pip install pdfplumber          # чтение pdf
pip install openpyxl            # если выгрузка в xlsx
```

Команда `scan` работает без `requests`: сеть используется только при обновлении.

## Использование

Адрес и формат выгрузки Минюста менялись, поэтому URL не вшит в код. `update` требует явного источника — ссылку либо уже скачанный файл.

```bash
# 1. Снимок реестра из локального файла (xlsx, csv, json, docx)
python inoagent_check.py update --from-file ~/Downloads/reestr.xlsx

# 1b. Либо по прямой ссылке на выгрузку
python inoagent_check.py update --url https://example.org/reestr.xlsx

# 2. Какие снимки есть локально
python inoagent_check.py snapshots

# 3. Вычитать документы (оффлайн)
python inoagent_check.py scan article.docx interview.pdf --out reports/

# 4. По состоянию реестра на дату публикации материала
python inoagent_check.py scan archive/2025-03-14.docx --as-of 2025-03-10

# 5. С проверкой конкретной формы маркировки
python inoagent_check.py scan repost.docx --disclaimer-file forms/author_2022.txt
```

Код возврата `1` — найдены упоминания без маркировки рядом. Удобно вешать на pre-commit или CI редакционного репозитория.

## Почему обновление не автоматическое

Обновление вызывается явно и никогда не происходит при старте `scan`. Три причины:

1. **Воспроизводимость.** Значение имеет состав реестра на дату вычитки. Если датасет меняется под ногами, вчерашний отчёт нельзя предъявить в споре.
2. **Тихий ложноотрицательный результат.** Формат выгрузки менялся (PDF, DOCX, XLSX). Сломанный парсер вернёт ноль записей, и утилита скажет «упоминаний нет» — худший возможный отказ. Поэтому `update` отказывается сохранять снимок, если разобрано менее 300 записей, если расхождение с предыдущим снимком превышает 25%, либо если ни в одной строке не распознана дата включения. Обход только через `--force`.
3. **Конфиденциальность.** Мы вычитываем чужие документы. Сетевой вызов при каждом запуске несовместим с обещанием оффлайна.

Каждый отчёт печатает дату снимка, число записей и его sha256.

## Что утилита проверяет и чего не проверяет

Проверяет:

- упоминания имён и наименований из реестра, включая падежные формы фамилий;
- наличие маркировки в окне ±600 символов вокруг упоминания;
- плашку в первых 800 символах документа — но только для того лица, чья фамилия в этой плашке названа;
- гиперссылки на ресурсы лиц из реестра;
- соотношение кегля плашки и основного текста (только для `docx`).

Не проверяет и не может проверять:

- относится ли материал к иноагентской деятельности — это содержательная оценка, её делает человек;
- контрастность цвета и визуальное оформление в pdf и изображениях;
- длительность демонстрации плашки в видео;
- актуальность правовых норм на момент запуска.

## Известные ограничения

- **Ложные срабатывания.** Порог уверенности по умолчанию `0.5`. Он выбран так, чтобы находились короткие фамилии вроде Быкова и Акунина, и это осознанно даёт лишние срабатывания на однофамильцах. Пропуск ведёт к предписанию, лишняя строка — к минуте работы редактора. Порог поднимается через `--min-confidence`.
- **Морфология правилами.** Падежные формы порождаются набором правил, без словаря. Редкие и иноязычные фамилии могут не попасть в выборку — это ложноотрицательный результат, самый опасный класс. Критичные персоны проверяйте вручную.
- **Разделение персона/организация грубое.** Строка из более трёх слов считается организацией. Длинное Ф. И. О. может попасть в организации и потерять падежные формы.
- **Плашка ищется как подстрока.** Маркировка, разорванная переносом или вставленная картинкой, не найдётся.
- **Снимки старее 23.08.2026 могут не содержать дат включения** из-за исправленного бага разбора даты. Для работы с `--as-of` пересоздайте снимок.
- **Правовые нормы меняются.** Тексты форм и пороги вынесены в файлы и подлежат сверке с первоисточником.

## Этическая рамка

- Телеметрии нет. Утилита не отправляет никуда содержимое документов и результаты.
- Автоматического удаления и правки текста нет. Только отчёт.
- Массовое сканирование внешних корпусов и построение баз упоминаний по людям не поддерживается и не будет добавлено.
- Реестр используется как официально опубликованный документ; утилита не расширяет его и не строит собственных списков.

## Оговорка

Проект носит вспомогательный характер. Он не заменяет проверку юристом и не даёт правовых гарантий. Сведения о нормах и практике собраны из открытых источников по состоянию на 23 августа 2026 года и могли измениться. Ответственность за публикуемые материалы несёт их автор и распространитель.
